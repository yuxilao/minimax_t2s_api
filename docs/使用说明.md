## 1. Windows 零安装使用

**你不需要安装 Python，也不需要装任何依赖。**

1. **下载**：到仓库的 **[Releases](https://github.com/yuxilao/minimax_t2s_api/releases/latest)** 页面下载最新版的
   `t2s-voice-tool.exe`（维护者打 `v*` 标签后由 GitHub Actions 自动构建并发布，无需登录即可下载）。
   exe 已内置 Python 运行时、PySide6、openpyxl、requests——**不需要安装任何依赖**。
2. **放置**：新建一个自己的文件夹（例如 `D:\语音工具\`），把 `t2s-voice-tool.exe` 放进去，**双击运行**。
   - 首次运行若出现 Windows SmartScreen 蓝框：点「更多信息」→「仍要运行」。
   - 单文件版首次启动需自解压，慢几秒属正常现象。
   - 建议不要把 exe 放在桌面/下载目录直接跑，放独立文件夹便于管理它生成的 `config.json`、`tasks.json` 和 `语音包\`。
3. **填 API Key**：在底部栏选好供应商，点「**⚙ 设置**」在对话框里填 **API Key**（以及音色 ID 等），点「保存」即写回
   `config.json`（Key 输入框带 👁 显示切换，其余合成参数也都在这个对话框里）。

   > 打包版是「冻结」运行：配置永远读写 **exe 同目录的 `config.json`**（任务记录 `tasks.json` 也在 exe 旁），
   > 源码目录里的 `config.json` 不会被用到。
4. **转换（「批量转换」页签）**：顶部「语音目录」区「浏览…」选中 `.xlsx`、选好解析器 → 点「**加载目录**」→
   在语言复选列表勾选要转的语言（**默认全选；全部不勾选 = 全部语言**，另有「全选 / 清空」按钮）→ 确认底部输出目录
   （默认 exe 同目录的 `语音包\`）→ 点「**开始转换**」。
5. **取结果（「任务中心」页签）**：选中任务 → 点「**刷新**」（或勾选「自动刷新（每 60 秒）」）→ 状态变成
   「**待下载**」后点「**下载并打包**」→ 音频落盘为 `语音包\<语言>\<语音ID>.mp3`，并生成 `<语言>.tar`，状态变
   「已完成」。用底部栏的「**打开**」直接取结果。失败/过期/丢失的任务点「**重试**」会按原词条重新提交。
   **结果文件约 9 小时过期，超 8 小时未下载界面会告警，请尽快下载并打包**。

**自定义解析脚本**：把写好的 `.py`（开发方法见 [技术文档](技术文档.md)）放到 **exe 同目录的 `parsers_custom\`**
文件夹里，重启 exe 即可在「解析器」下拉框中看到它（无需重新打包）。

## 2. 界面总览

主窗口自上而下：

| 区域 | 内容 |
|------|------|
| 顶部「**语音目录**」共享区 | 目录文件 + 浏览 + 解析器 +「加载目录」；批量与单条页签**共用**解析结果 |
| 「**批量转换**」页签 | 选语言、开始转换；batch 模式提交即返 |
| 「**单条转换**」页签 | 一次转一条，即时试听 |
| 「**任务中心**」页签 | 任务刷新、下载并打包、重试 |
| 底部栏 | 输出目录 + 浏览 + 打开 ｜ 供应商下拉 + 音色摘要 +「⚙ 设置」 |

配置**启动自动加载**；供应商与合成参数（API Key、音色、语速/音量/音调、采样率/比特率/格式/声道等）都收纳在
「⚙ 设置」对话框里，保存即写回 `config.json`，没有单独的「加载配置/保存配置」按钮。

## 3. 批量转换

操作流程见 [第 1 节](#1-windows-零安装使用) 第 4 步。这里说明三种合成模式（「⚙ 设置」里 `tts_mode` 切换）：

| 模式 | 行为 | 适用 |
|------|------|------|
| `batch`（**默认**） | 所有选中语言的词条合并为一个 zip、**只创建 1 个任务**整批转换；GUI「开始转换」**提交即返**，之后到任务中心「下载并打包」 | 正式批量出包 |
| `sync` | 逐条同步请求，短文本秒级出结果；界面阻塞跑完直接落盘 | 小批量/试用/演示 |
| `async` | 逐条创建异步任务，界面阻塞跑完直接落盘 | 需要逐条独立任务时 |

- batch 模式下语言越多、条目越多，只是这一个任务处理更久，**不会变成多次任务**。
- 中途「取消」只对提交前的本地工作 / 逐条模式有效；batch 已提交的任务在服务端继续跑，由任务中心接管。
- 空文本条目自动跳过、不消耗配额，最终计入该语言「缺失」。

## 4. 任务中心

batch 模式提交即返，任务的后续生命周期集中在这里管理。

**任务状态机（生命周期）**：

```
[批量转换页签「开始转换」/ 任务中心「重试」── 提交 1 个任务、写入 tasks.json]
                          │
                          ▼
                   processing 处理中
                      │
                      ├─ 查询仍是处理中 ────────▶（留在 processing，继续刷新）
                      ├─ 查询返回 failed ───────▶ failed   失败    ┐
                      ├─ 查询返回 expired ──────▶ expired  已过期  ├─「重试」＝用记录里的词条快照
                      ├─ 查询「任务不存在」──────▶ lost     记录丢失 ┘   重新提交（新 task_id、
                      │                                                 attempts+1，回到 processing）
                      └─ 查询返回 success ──────▶ success  待下载
                                                  │
                                    点「下载并打包」┤
                                                  ▼
                                         downloading 下载中
                                            │          │
                          解包+逐条落盘+打 tar          下载/解包失败（状态回滚）
                                            ▼          ▼
                              packaged 已完成      success 待下载
                              （终态）             （可再点一次「下载并打包」）
```

| 状态 | 界面显示 | 含义 | 可做的操作 |
|------|------|------|------|
| `processing` | 处理中 | 已提交，服务端整批转换中 | 刷新 |
| `success` | 待下载 | 服务端已完成，结果文件已拿到（**约 9 小时过期**） | 刷新、**下载并打包** |
| `downloading` | 下载中 | 下载/解包/打包进行中（中间态，防重入） | 等待 |
| `packaged` | 已完成 | 已落盘并生成各语言 tar（终态） | 删除记录 |
| `failed` | 失败 | 服务端任务处理失败 | **重试** |
| `expired` | 已过期 | 结果文件在服务端已过期 | **重试** |
| `lost` | 记录丢失 | 查询返回「任务不存在」 | **重试** |

**列表列**（与界面表头一致）：任务ID / 语言 / 条数 / 状态 / 已提交（相对时间）/ 结果文件ID / 最近错误与缺失。
状态列按颜色区分，支持多选（多选时「下载并打包」「重试」按选中顺序逐条排队执行）；列表底部固定一行
「结果文件约 9 小时过期」的提示。

**操作**（都在后台线程串行执行，界面不卡）：

| 按钮 | 行为 |
|------|------|
| 刷新 | 对选中记录逐条查询更新状态；未选中时刷新全部非终态记录 |
| 自动刷新（每 60 秒） | 勾选后每 60 秒自动刷新一次全部非终态记录，默认关闭 |
| 下载并打包 | 下载结果 → 解包 → 逐条落盘 `<语言>/<语音ID>.mp3` → 每语言生成 `<语言>.tar` → 置「已完成」；中途失败回滚为「待下载」，可再次点击 |
| 重试 | 对失败/已过期/记录丢失的任务，用保存的**词条快照**重新提交（新任务 ID，不用重新选语言） |
| 删除记录 | 弹确认框后仅删任务记录，**不影响已落盘的音频与 tar** |

**⚠ 9 小时过期警示**：任务成功后结果文件约 **9 小时**内可下载。「待下载」状态**超过 8 小时**仍未打包时，界面会告警
（每条任务只提示一次）。建议：**开启「自动刷新」，任务完成后尽快下载并打包**；一旦过期，只能「重试」重新提交并
再次消耗配额。

**任务记录文件 `tasks.json`**：与 `config.json` **同目录**（打包版在 exe 旁，源码运行在项目根）。程序崩溃不会写出
半截文件；记录内含词条**文本快照**（供「重试」原样重提交），**不含 API Key**；换机器时把 `config.json` 与
`tasks.json` 一起拷走即可延续任务列表。**删除 `tasks.json` 只会丢任务列表，不影响已落盘的语音文件。**

## 5. 单条转换

「单条转换」页签用于**一次只转一条**——抽一条词条即时出音频，试听文本与音色效果：一次请求直接返回音频，
不创建任务、无需轮询、也不进任务中心。

```
顶部选目录文件 ─▶ 「加载目录」 ─▶ 选语言 ─▶ 选语音ID（可关键字过滤，文本预览） ─▶ 「转换」 ─▶ <输出目录>/<语言>/<语音ID>.mp3
```

1. 在顶部共享区选目录文件（选好解析器），点「加载目录」（解析结果与批量页签共用）；
2. **先选语言**，再**选语音 ID**（可用关键字过滤缩小范围）——选中后可见**文本预览**，空文本条目标注
   「无法合成」且「转换」按钮禁用；
3. 点「转换」，音频同步返回后立即落盘；成功后状态行显示输出路径，可点「**打开所在目录**」直接定位文件。

**输出**：只写单条 `<输出目录>/<语言>/<语音ID>.mp3`（输出目录是底部栏的全局设置，批量与单条共用），
**不打 `<语言>.tar` 包**。合成参数（音色、语速等）统一在「⚙ 设置」对话框里配置。

**注意**：

| 事项 | 说明 |
|------|------|
| 空文本 | 标注「无法合成」并禁用「转换」，**不发请求、不消耗 API 配额** |
| 取消 | 页签不提供「取消」：同步请求一旦发出即不可中断，只能等待返回 |
| 离线演示 | 供应商选 `fake` 可完整走一遍流程（不联网、不扣配额），适合无 Key 时演示界面操作 |

## 6. 配置说明

配置文件为 JSON，一般通过 GUI「⚙ 设置」对话框修改即可。完整结构如下（即内置默认值，把 `api_key` 换成自己的
Key、`voice_id` 换成目标音色即可用）：

```json
{
    "provider": "minimax",
    "providers": {
        "minimax": {
            "api_key": "",
            "base_url": "https://api.minimaxi.com",
            "model": "speech-2.8-turbo",
            "voice_setting": {
                "voice_id": "male-qn-qingse",
                "speed": 1.0,
                "vol": 1.0,
                "pitch": 0
            },
            "audio_setting": {
                "audio_sample_rate": 32000,
                "bitrate": 128000,
                "format": "mp3",
                "channel": 2
            },
            "poll_interval": 10,
            "poll_timeout": 1200,
            "concurrency": 5,
            "tts_mode": "batch",
            "sync_max_chars": 9000,
            "request_timeout": 30,
            "upload_timeout": 120,
            "download_timeout": 60
        }
    }
}
```

常用字段：

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `api_key` | — | **必填**。MiniMax API Key |
| `model` | `speech-2.8-turbo` | 模型标识符，见下表 |
| `voice_setting.voice_id` | `male-qn-qingse` | 音色 ID（整批共用一个音色） |
| `voice_setting.speed` / `vol` / `pitch` | `1.0` / `1.0` / `0` | 语速 0.5~2.0；音量 0~10；音调 -12~12 |
| `audio_setting.*` | 32000 Hz / 128000 / mp3 / 声道 2 | 音频参数，一般不用改 |
| `tts_mode` | `batch` | 合成模式，见[第 3 节](#3-批量转换) |
| `poll_timeout` | `1200` | 单个任务轮询超时（秒，20 分钟）；batch 全量跑时可调大到 `1800`~`3600`（GUI 任务中心不受它约束） |
| `concurrency` | `5` | 并发数，**仅 sync/async 逐条模式生效**；免费/限流账户建议 `2`~`3`，过大易触发 429 限流 |
| `sync_max_chars` | `9000` | sync 模式单条文本上限，超过自动回退异步链路 |

其余（`base_url`、`poll_interval`、各超时项）保持默认即可。

**支持的模型**（以账户实际权限为准，报「model 无权限」时换一项）：

| 模型标识符 | 说明 |
|-----------|------|
| `speech-2.8-turbo` | 2.8T turbo 速度版（推荐，默认） |
| `speech-2.8-hd` | 2.8T 高清版 |
| `speech-2.6-hd` | 2.6T 高清版 |
| `speech-2.6-turbo` | 2.6T turbo 速度版 |

### 旧版配置自动迁移

老版本 `config.json` 是扁平结构（顶层直接放 `api_key` / `model` / `voice_setting` / `audio_setting`）。
加载时会自动识别并迁移为新结构，**无需手工改写**。

### 配置与任务记录的存放位置

| 运行方式 | 默认配置文件 | 任务记录 | 默认输出目录 | 自定义解析器目录 |
|----------|--------------|----------|--------------|------------------|
| 打包版（exe 双击） | `exe 同目录/config.json` | `exe 同目录/tasks.json` | `exe 同目录/语音包` | `exe 同目录/parsers_custom` |
| 源码运行 | `项目根/config.json` | `项目根/tasks.json` | `<输入文件所在目录>/语音包`（CLI）／`项目根/语音包`（GUI） | `项目根/parsers_custom` |

### 安全提醒

- **切勿**把含真实 `api_key` 的 `config.json` 提交到版本库（`.gitignore` 已忽略 `config.json`）。
- `tasks.json` 不含 Key，但保存了**词条文本快照**；外发或提交版本库前请确认文案是否敏感。
- 分享打包版给他人时只给 exe，让对方自己填自己的 Key；不要把带 Key 的整个文件夹压缩包外发。
- 疑似泄露时立刻到 MiniMax 控制台吊销/轮换 Key。

## 7. 语音目录格式

内置解析器 `xlsx_9lang` 对 Excel 的要求：

- 只读**第一个工作表**；**首行为表头**，表头列名（除跳过列外）即语言名，语言数量不限。
- **首列 = 语音 ID**，必须匹配 `Q+数字`（如 `Q001`、`Q8107`）；首列为空的行跳过，ID 非法但有内容的行记警告并跳过，
  重复 ID 自动去重。
- 跳过列：`AP音效名称`、`场景详细描述`（可有可无，列顺序任意）。
- 单元格内换行会被替换成空格；空文本条目保留（合成时跳过，计入缺失）。

示例：

| 语音ID | 中文 | 英文 | 俄语 | AP音效名称 | 场景详细描述 |
|--------|------|------|------|-----------|--------------|
| Q001 | 您好，请系好安全带 | Hello, please fasten your seatbelt | Здравствуйте, пристегните ремень | ding | 登机提示 |
| Q003 | 航班即将起飞 | The flight is about to take off | Рейс скоро вылетает | bell | 广播 |

产出 `语音包/中文/Q001.mp3`、`语音包/中文.tar` …

目录不是这种格式？支持自定义解析器：把解析脚本放进 `parsers_custom/` 目录即可被自动加载（开发方法见
[技术文档](技术文档.md)）。

## 8. 输出结构与注意事项

```
输出目录/
├── 中文/                 # 每种语言一个子目录
│   ├── Q001.mp3
│   └── Q003.mp3
├── 中文.tar              # 同语言的 tar：顶层扁平，只含 Q001.mp3 …
├── 英文/
│   └── …
└── 英文.tar
```

- **tar 内为扁平结构**（成员名就是 `<语音ID>.mp3`），可直接作为语音包交付。
- **空文本条目跳过合成**：不请求 API、不落盘，计入该语言「缺失」。
- **缺失/未知**：`缺失` = 目录里有但没拿到音频；`未知` = 音频里有但目录里没有的语音 ID（正常应为 0）。
- **结果下载有效期**：任务成功后音频**约 9 小时内**可下载，过期只能重试（再次消耗配额）。GUI batch 模式下
  **超 8 小时未下载任务中心会告警**，请及时归档 `语音包/` 目录。
- **重跑会覆盖**同名 mp3/tar 并再次消耗配额；只想补跑部分语言时，只勾选这些语言。
- **失败的影响范围**：batch 模式任务级失败会让本次转换的**全部语言条目**计入缺失——在任务中心点「重试」即可
  （用词条快照重新提交，不用重新选语言）；sync/async 逐条模式下单条失败只记 warning 继续。
  但**认证失败 / 配额超限（429）属全局错误，会立即终止整批**，先解决 Key/额度问题再重跑。

API 参考：
[创建异步语音合成任务](https://platform.minimaxi.com/docs/api-reference/speech-t2a-async-create) ·
[查询任务状态](https://platform.minimaxi.com/docs/api-reference/speech-t2a-async-query)

## 9. 常见问题

### API 配额不足

**表现**：报「配额超限」「quota」「limit」或 429。
**解决**：登录 MiniMax 控制台确认额度；等待重置或申请提额；batch 模式请求数最少（按字符量计费，拆任务不省额度）；
逐条模式调低 `concurrency`；先用 `fake` 供应商验证目录格式，再消耗配额。

### 合成速度 / 如何提速

默认 `batch`：一次转换只创建 1 个任务，服务端整批处理约**数分钟**。小批量试跑可临时改 `sync`（短文本约
**0.7 秒/条**）；调大 `concurrency` 可提速逐条模式，但过高可能触发限流（429 会整批终止）。

### 认证失败

**表现**：`认证失败，API Key 无效或已过期`、`401 Unauthorized`、`403 访问被拒绝`。
**解决**：确认 `api_key` 正确无多余空格、未过期、已开通 TTS 权限；打包版检查的是 **exe 同目录**那份
`config.json`（改完重启 GUI，或直接在「⚙ 设置」里改并保存）；换个 `model` 试权限差异。

### 网络错误

**表现**：`网络连接失败`、`请求失败`、`请求超时`。
**解决**：检查外网可达 `api.minimaxi.com`、代理/防火墙；调大 `request_timeout`/`download_timeout`；
网络抖动直接重跑，GUI 任务到任务中心「刷新」/「重试」。

### 任务查询超时

**表现**：`轮询: 任务查询超时（已等待 1200 秒）`（CLI / 逐条模式）。
**解决**：`poll_timeout` 按**单个任务**计（默认 20 分钟），全量跑时可调到 `1800`~`3600`；CLI 超时后任务其实还在
服务端跑，可稍后重跑，或改用 GUI：**提交即返 + 任务中心多次「刷新」**，不受超时约束。

### 任务处理失败 / 结果异常

**表现**：`任务处理失败`、`任务已过期`，或完成后大量条目「缺失」。
**解决**：检查文本是否超长或含异常字符；换 `voice_id` 重试；GUI 在任务中心点「**重试**」（用词条快照重新提交，
不用重新选语言、不用重新解析目录）。

### 任务中心相关

- **提交后列表里没有记录**：任务记录只在 **GUI** 的 batch 模式写入；CLI、`fake` 供应商、非 batch 模式不落记录。
  打包版检查 **exe 同目录**的 `tasks.json` 是否可写（放 `Program Files` 会写失败并报错）。
- **一直是「处理中」**：点「刷新」触发一次查询；勾选「自动刷新（每 60 秒）」交给它自己刷。
- **「下载并打包」点了没反应 / 报「任务正在下载打包中」**：同一记录的操作在后台串行，等前一个完成；只有「待下载」
  状态可下载打包。
- **下载中途失败**：状态自动回滚为「待下载」，再点一次即可（不必重新提交）。
- **「删除记录」后音频不见了**：删除只清任务记录，不碰已落盘文件；音频不在多半是当时没点「下载并打包」，
  或输出目录选错了。
- **重复下载会怎样**：同名文件被覆盖（内容一致），不额外消耗配额。

### 解析相关

**表现**：`没有解析器能识别该文件`、`未找到任何语言列`、大量「语音ID非法，已跳过」。
**解决**：确认首列表头是语言名、首列数据是 `Q` 开头数字 ID；确认没有把说明行放在首行；换格式就写自定义解析器
（见 [技术文档](技术文档.md)），或手工指定解析器。

### 打包 / exe 相关

- **双击没反应 / 首次启动慢**：onefile 需自解压，等几秒；被杀软拦截时加信任。
- **exe 报 `No module named 'openpyxl'`**：构建环境漏装依赖，重新打包（见[技术文档](技术文档.md)）。
- **GUI 打不开（源码运行）**：确认已 `pip install -r requirements.txt`；Linux 桌面报
  `Could not load the Qt platform plugin "xcb"` 是缺 `libxcb-cursor0`，`sudo apt install libxcb-cursor0`
  即可（打包版已内置，不受影响）。
- **配置写了但不生效**：确认改的是 exe 同目录的 `config.json`，改完重启 GUI。
- **任务中心列表是空的**：任务记录读的是 **exe 同目录的 `tasks.json`**；换文件夹存放 exe 等于换了一份记录
  （把旧 `tasks.json` 一起拷过去即可延续）。
- **输出目录写入失败**：exe 所在目录不可写（如 `Program Files`）或磁盘满，换到用户目录。
